# 面试题设计原则与题库框架

> 本文件指导 SKILL.md Step 3 如何设计高质量面试题。

---

## 核心设计原则

### 1. JD 驱动
每道题都要能对应 JD 中的至少一个要求或加分项。在题目后标注「📌 考察点」时，引用 JD 原文关键词。

### 2. 简历锚点
至少 3 道题要与简历中的具体项目/经历挂钩，让候选人感受到「面试官真的看过我简历」。
格式：「你简历上提到在 XX 公司做了 XX 项目，当时……」

### 3. 由浅入深
题目排序遵循：破冰题（Q1）→ 专业基础（Q2-Q4）→ 项目深挖（Q5-Q7）→ 行为/价值观（Q8-Q9）→ 收尾/反问（Q10）

### 4. 追问预设
每道题配备 1~2 个追问方向，便于用户模拟真实面试的「被追问」感。

### 央国企 / 运营商 / 银行信息化岗（校招版）

> 面向**央国企 / 运营商 / 银行信息化岗校招**（按用户实际投递方向配置：运营商、银行科技岗、央企信息化、技术支持类）。题型与互联网大厂完全不同：**结构化/半结构化 + 稳定性 + 岗位业务理解为主，不考算法**（除非明确笔试）。行为题题库见 `bei-framework.md`，岗位职责参考用户笔记库岗位材料（注意可能过期）。

| # | 类型 | 示例 |
|---|------|------|
| Q1 | 破冰/自我介绍 | 「请做 2 分钟自我介绍」——按笔记库行为题素材的定稿版：学历+主攻方向+三段核心经历+匹配点 |
| Q2 | 求职动机/岗位认知 | 「为什么应聘我们公司、这个岗位？」——公司业务（结合岗位职责说 1-2 句）+ 岗位职责概括 + 匹配点 + 非海投证据 |
| Q3 | 稳定性/意愿 | 「为什么选这个城市？家人支持吗？能接受加班/岗位调剂/偏远地区/轮岗吗？」——按笔记库行为题素材答题公式 |
| Q4 | 技术基础（只考真实用过的） | Java/Spring Boot 基础、MySQL、Docker、接口联调——从项目证据映射表里挑，不考没出现的框架 |
| Q5 | 项目深挖（最高权重） | 「讲一下你的毕设/微服务项目/实习，最大的难点、选型和决策」——必须基于阶段 2 证据映射表 |
| Q6 | 项目追问/排错复盘 | 「项目里遇到最难排查的问题？怎么定位解决的？」——对应困境应对故事模块 |
| Q7 | 岗位业务理解 | 运营商：「怎么看运营商数字化转型/创新技术支撑岗的定位？」；银行：「对数据/合规/安全的理解？」；央企：「信息化建设怎么做？」 |
| Q8 | AI 应用差异化（加分项） | 「你在 AI 应用方向做了什么？讲讲 RAG/Agent 项目」——对应 AI 应用岗题库 |
| Q9 | 行为面试 | 「说一个你克服困难的经历 / 最成功的事」——按 bei-framework 题库 + 三类故事模块 |
| Q10 | 反问 | 「你还有什么想问的？」——按笔记库行为题素材反问清单 |

> 央国企加分答法：**稳定性（地域+党员+长期意愿）+ 岗位理解（看过岗位职责）+ 项目讲得实**，比炫技术更有区分度。技术题深挖但不过度（点到项目真实用到的即可）。

### AI 应用岗（校招 / 应届版，面向 RAG / Agent / Dify 类项目）

适用于 AI 应用开发、大模型应用、智能体、知识库类岗位的**校招**面试。题目必须落回用户实际项目（如 RAG 知识库问答、Agent 应用），不考没做过的框架。

| # | 类型 | 示例 |
|---|------|------|
| Q1 | 项目链路 | 「从用户提问到最终回答，完整链路走一遍（输入→检索→组装→生成→输出）」 |
| Q2 | 知识库构建 | 「文档怎么切分的？chunk 大小怎么定的？为什么？检索效果怎么验证的」 |
| Q3 | 向量检索 | 「向量化用的什么模型？相似度用什么算？召回结果排序逻辑？」 |
| Q4 | RAG 原理 | 「为什么不直接把文档塞给大模型？RAG 解决什么问题？什么时候该用 RAG 而不是微调？」 |
| Q5 | 幻觉治理 | 「如果回答里出现知识库里没有的内容，怎么发现、怎么防？」 |
| Q6 | 提示词工程 | 「系统提示词怎么设计的？角色设定和规则约束怎么写才稳定？」 |
| Q7 | Agent 编排 | 「多步任务（查知识库→调用工具→生成）怎么编排的？工作流节点间数据怎么传？」 |
| Q8 | 模型选型 | 「为什么选这个模型（如 DeepSeek）？API/本地部署怎么权衡？成本、延迟、效果各看什么？」 |
| Q9 | 评估与迭代 | 「上线后怎么知道它答得好不好？问答对怎么沉淀？效果怎么持续优化？」 |
| Q10 | 工程化 | 「密钥怎么管理？并发怎么控？上线（云服务器/公网访问）怎么做的？有哪些坑？」 |

> 校招 AI 应用岗加分答法：把「检索质量 → 幻觉 → 评估 → 迭代」闭环讲清楚，比背 Transformer 结构更有区分度。

## 题目难度分级（按目标职级）

| 职级 | 难度定位 | 说明 |
|------|---------|------|
| 应届/P4 | 基础扎实 | 数据结构/算法/框架基础，项目说清楚 |
| P5 | 有深度 | 能独立解决复杂问题，有一定系统设计能力 |
| P6 | 引领级 | 架构能力、跨团队影响力、业务 sense |
| P7+ / 管理岗 | 战略级 | 业务战略判断、团队建设、上下对齐 |

## 校招权重（应届生/校招岗适用）

出题排序与深挖优先级：

1. **项目深挖（最高权重）**：能讲清 1 个项目的完整链路、决策、难点，比任何八股都有区分度
2. **基础原理（次高）**：只考项目里真实用到的（用了 Spring 考 IoC/事务，用了 Redis 考缓存一致性），不考没出现过的框架
3. **算法（按需）**：央国企/银行/事业单位不考算法题（除明确笔试）；大厂才准备 LeetCode
4. **行为/稳定性（央国企必考）**：职业规划、稳定性、党员身份、服务意识

**央国企/运营商/银行权重**（央国企/银行校招优先这套）：
1. **稳定性与动机（最高）**：为什么选我们/这个城市、家人支持、职业规划、党员身份、能接受加班/调剂——这部分答不好直接挂，比技术更重要
2. **项目深挖（次高）**：毕设/微服务/实习讲得实、有量化、有决策
3. **岗位业务理解**：看过岗位职责、知道岗位做什么、结合公司业务说 1-2 句
4. **技术基础**：项目真实用到的；技术深挖但不炫技
5. **算法**：不考（除非笔试明确）

校招题总量控制：10 问中项目相关 ≥5 问。

## 输出质量 checklist

生成 10 问前确认：
- [ ] 至少 3 题锚定简历具体经历
- [ ] 至少 2 题直接对应 JD 关键要求
- [ ] 包含至少 1 道行为面试（BEI/STAR）题
- [ ] 包含至少 1 道开放性思维题
- [ ] 题目语气符合目标公司面试风格
- [ ] 每题配备追问方向
- [ ] **央国企/银行岗**：含稳定性/动机题、岗位认知题、项目深挖题；不出现算法题（除非笔试明确）
