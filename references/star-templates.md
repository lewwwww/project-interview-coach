# 好答案 vs 差答案（STAR Templates）

> 用于「好答案 vs 差答案」专项模式：对同一道题，给出真实候选人水平的两个版本，让用户看清差距在哪。

## 双模板结构

对每道重点题输出：

```markdown
### 题目：<问法>

**差答案（像真实候选人，不是故意写烂）**
<口语化、但空泛/缺证据/有典型毛病的版本>

**差在哪**
- 只有结论没有过程
- 数字没有来源
- 「我们」模糊了个人贡献
- 关键概念说不清

**好答案**
<结构完整、有代码证据、能接追问的版本>

**好在哪**
- STAR 结构完整，Action 最详细
- 数字有来源或明确标注
- 「我」清晰
- 主动埋了可追问的点
```

## 常见「差答案」毛病清单（对照用）

| 毛病 | 例子 | 修正 |
|---|---|---|
| 空泛结论 | 「我优化了性能」 | 「接口 RT 从 800ms 降到 200ms，压测报告 100 并发」 |
| 背诵腔 | 「这里运用了缓存穿透的解决方案」 | 用自己的话讲：布隆过滤器先拦、查不到也缓存 |
| 全用「我们」 | 「我们做了防超卖」 | 「防超卖的逻辑是我写的，在 OrderServiceImpl 第 42 行」 |
| 编造/夸大 | 「支撑 3000 万用户」 | 「系统设计容量是这个量级，实际并发压测到 X」 |
| 有头无尾 | 「遇到了难题，最后解决了」 | 难题 → 排查过程 → 根因 → 解法 → 验证 |

## 反 AI 味硬规则（所有输出生效）

1. 禁开场白："Great question!"「这是一个好问题」「让我们从…开始」「总的来说」。
2. 禁给用户「背台词」：不把「这里运用了 XX 方案」当标准答案塞给用户——概念必须用户自己能解释。
3. 句式有长短变化，不全是并列短句；书面材料允许分点，口语材料写成自然说话的样子。
4. 具体证据 > 泛泛表扬：不说「答得很好」，说「你把超时重试和幂等区分开了」。
5. 没信息量的句子直接删（「需要注意的是/值得注意的是/综上所述」）。
6. 弱答时给同深度小提示，不把完整答案当奖励甩出去。

## 央国企 / 银行场景补充

- 行为题多考：稳定性（为什么不考研/为什么不选互联网）、党员身份与组织生活、基层服务意识、公文/汇报能力、职业规划与编制诉求。
- 好答案要体现：表达正式但不背稿、真实动机 + 向前看、对体制内工作节奏有认知。
- 差答案典型：贬低前东家/互联网、空喊「为人民服务」、把考编说成「图稳定想躺平」。
