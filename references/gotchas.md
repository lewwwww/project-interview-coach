# 踩坑记录（Gotchas）

> 改造与使用本 skill 时踩过的坑。每次遇到新坑，加在这里。

## 安装 / 触发类

- **改完 skill 必须新开会话才生效**：Codex/豆包对 skill 的加载发生在会话启动时，中途改了 SKILL.md 不重开会话看不到变化。
- **触发靠 description**：用户的话匹配到 description 才触发；description 写「什么时候用」而不是功能介绍。
- **前缀调用**：Codex 里可 `@project-interview-coach` 强制触发；豆包里靠描述自动匹配，必要时让用户点名项目名。
- **软链接/复制到 codex skills 目录**：本仓库在 D 盘，用之前复制或软链到 `~/.codex/skills/`，否则 Codex 不识别。

## 出题 / 内容类

- **不编造项目细节**：题目和答案只来自代码证据映射表；用户没写进描述/简历的东西不能当事实问。
- **AI 应用岗题库别背八股**：RAG/Agent 的题要落回用户项目（Dify 工作流、向量库、幻觉治理），不考没做过的框架。
- **央国企不是大厂**：公司风格表默认走央国企分支，别把字节的「算法题必考」套到税务岗。
- **数字必须有来源**：QPS/并发/优化百分比，追问压测报告或日志，没有就标未核验。

## 交互类

- **一问一答**：模拟面试一次一题；用户没答完之前不给参考答案。
- **逐阶段确认（阶段门控）**：整个主流程每个阶段输出后必须停下等用户确认，用户说「继续」才进下一阶段；**严禁一口气把阶段 0-7 全输出**——用户要的是边确认边推进。
- **用户自己测**：拿不准的答案交给用户实测（本项目用户偏好），skill 只给方案和预判。

## 反模式提醒（源自「我写了 50 个 Claude Code Skill」）

- SKILL.md 别超过 500 行（本文件约 80 行，控制住）。
- references 只放一层深，不放嵌套子目录。
- 每个 reference 职责单一，不互相抄。
- 示例必须完整可运行，不用伪代码糊弄。
