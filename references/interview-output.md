# 面试弹药输出（Interview Output）

> 阶段 7 的产物：一个项目输出**两份文件**，格式对齐用户本地笔记库的作战卡 / 代码与场景题系列（可配置）——但命名用项目名，不用编号。

## 输出两份文件

### 文件 1：`<项目名>-面试作战卡.md`（对齐用户本地笔记库的作战卡格式）

#### 1. 项目定位（放最前）

```
项目名称：<项目名>
经历类型：<如 软件公司 Java 开发实习 / 毕业设计 / 独立开发>
岗位角色：<如 Java 开发实习生 / 负责人>
重要程度：<最高 / 高，哪个岗位优先展开>
一句话定位：<解决什么问题 + 给谁用 + 我的角色>
项目描述：<简历里的项目描述原文，面试前念一遍>
```

#### 2. 钩子对照表（简历词 → 面试官可能问 → 答案在哪）

```
| 简历上的钩子 | 面试官可能问 | 答案在哪里 |
|------------|------------|-----------|
| <技术词/模块词> | <具体问法> | <作战卡第 X 节；对应本地八股笔记相应章节> |
```

> 目的：面试前知道「简历上的每个词都能扛住」。钩子来源 = 简历项目描述里的字面词 + 技术栈词；简历里没有的不写。

#### 3. 30 秒版（自我介绍用，一气呵成）

```
<项目是什么，一句话>
<我主要负责什么，一个模块>
<技术栈，两三个关键词>
<可验证的结果，一句>
```

#### 4. 1 分钟版（STAR，Action 最详细）

```
S：背景——项目要解决什么问题，当时的处境
T：我的职责——我具体负责哪一块
A：我做了什么——动作、选型、解决的具体难点（占 60% 篇幅）
R：结果——可验证的产出；学到什么 / 下次怎么做更好
```

#### 5. 深挖弹药库（被追问时翻）

- **业务逻辑**：核心用户流程/管理流程一句话链路（对齐本地作战卡「业务逻辑」节）
- **技术架构**：分层/服务结构一句话（后端分层、前端部署形态，对齐本地作战卡「技术架构」节）
- **重要选型**：为什么这么选 + 备选 + 代价（标注推断还是代码支撑；对齐本地作战卡「技术选型」节）
- **一个端到端功能**：从入口到落库的完整链路 + 代码路径
- **一个证据化难点**：只写有证据的（已核验/代码支撑）；没有证据的标成「可能的风险场景」
- **疑难排查套路**：通用排查步骤（定位→查资料→工具/方案→解决），对齐本地作战卡「疑难问题」节
- **一个工程质量话题**：测试/日志/监控/异常处理现状
- **一个条件改进**：如果重做，改什么？触发信号？成本？（不写"加 Redis/MQ"式空话）
- **八股挂靠点**：项目没用但面试官爱引申的（JVM/并发/集合/网络），每个挂靠点一句话怎么从项目引出去，对齐本地作战卡「八股挂靠点」节

#### 6. 高频问答 Q&A（10 问里最可能被问的 3-5 题）

```
Q：<面试官最可能的问法>
A：<口语化回答，含代码证据和数字>
追：<可能跟进的追问 + 应对>
```

### 文件 2：`<项目名>-代码与场景题.md`（对齐用户本地笔记库的代码与场景题格式）

> 选项目里最重要的 2-4 条核心链路（如：登录鉴权 / AI 问答接入 / 下单防超卖），每条链路按下面骨架组织——面试官从任意环节切进来都能接住。

#### 每条链路的固定骨架

```
### 链路 N：<链路名>
**N.1 场景 × 八股（一问一答）**
  <面试官视角的场景问法> → <一句话答案，含项目证据>
**N.2 八股考点（一句话速记，背这个就够）**
  - 考点 A：<一句话>
  - 考点 B：<一句话>
**N.3 代码实现（对照项目真实代码）**
  <关键文件/函数路径 + 2-3 行核心逻辑>
**N.4 链路追踪（一次请求全流程，面试按这个讲）**
  入口 → 校验 → 核心处理 → 落库/外部调用 → 返回，每步一句话
**N.5 追问应对**
  <最可能的追问 + 应对>
```

#### 文件末尾：疑难场景速记（对齐本地代码与场景题「疑难场景速记」节）

```
### 疑难场景速记（现象 → 原因 → 解决）
- 场景 1：<现象> → <原因> → <解决>
- 场景 2：<现象> → <原因> → <解决>
```

> 面试讲法：从一次请求的入口到出口，每一步讲「发生了什么 + 涉及什么八股」。

## 写入位置

- 默认：`<你的笔记库>\项目\面试作战卡\`（两份都写这里；该目录存在时推荐）
- 备选：用户指定路径（可参考用户本地笔记库的既有作战卡 / 代码与场景题同风格）；**不写进项目 README**（除非用户明确要求）
- 文件已存在：保留无关内容，只更新对应项目小节，不整篇覆盖

## 硬规则

- 量化数字必须有来源，否则标「未核验」或改定性。
- 口语化，禁止「运用了缓存穿透/雪崩解决方案」这类背诵腔——概念必须能用自己的话解释。
- 钩子对照表里的每个钩子，必须能在简历项目描述里找到字面词；简历里没有的不写。
- 代码与场景题里的每个链路，必须有真实代码路径支撑；讲不清的链路不写。
- 准备 4-6 张卡覆盖不同能力标签（技术深度/问题解决/协作/主导意识/学习速度），每张卡对应能答的问题类型。
